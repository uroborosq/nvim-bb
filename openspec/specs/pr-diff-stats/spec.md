# pr-diff-stats Specification

## Purpose

Показывает в PR Info объём PR: сколько файлов он затрагивает и сколько строк в нём добавлено и удалено, чтобы оценить размер ревью без перехода в Bitbucket.

## Requirements

### Requirement: Строка статистики в PR Info
Окно PR Info для PR открытой вкладки этого PR SHALL показывать в шапке, сразу после строки `Opened:`, строку `Changes: <N> files, +<added> -<deleted>`. Строка SHALL показываться и для своих, и для чужих PR, в любом режиме diff вкладки.

#### Scenario: PR с изменениями в нескольких файлах
- **WHEN** PR изменяет 14 файлов, в которых добавлено 345 и удалено 67 строк, и пользователь открывает PR Info во вкладке этого PR
- **THEN** в шапке PR Info после строки `Opened:` выводится `Changes: 14 files, +345 -67`

#### Scenario: Конфликт слияния
- **WHEN** у PR конфликт с target-веткой, и пользователь открывает PR Info во вкладке PR
- **THEN** строка `Changes:` стоит после `Opened:`, а строка `Merge: CONFLICT ...` — после неё

#### Scenario: Свой PR
- **WHEN** пользователь открывает PR Info во вкладке PR, автором которого является он сам
- **THEN** строка `Changes:` выводится так же, как для чужого PR

### Requirement: Статистика совпадает с diff PR в Bitbucket
Статистика SHALL считаться по тому же диапазону, что и diff PR в Bitbucket: от merge base ветки PR и target-ветки до вершины ветки PR. Переименованный файл SHALL считаться одним файлом, а в строки SHALL входить только его фактические изменения. Изменения только в пробелах SHALL учитываться. Изменения target-ветки после ответвления SHALL NOT влиять на статистику.

#### Scenario: Переименование с правкой
- **WHEN** PR переименовывает `a.go` в `b.go` и добавляет в него одну строку
- **THEN** этот файл учитывается как один файл с `+1 -0`

#### Scenario: Target-ветка ушла вперёд
- **WHEN** после создания PR в target-ветку влиты другие изменения, а ветка PR не менялась
- **THEN** статистика PR не меняется

### Requirement: Бинарные файлы
Бинарный файл, изменённый в PR, SHALL входить в число файлов и SHALL NOT влиять на число добавленных и удалённых строк.

#### Scenario: PR с картинкой
- **WHEN** PR изменяет один текстовый файл (`+10 -2`) и добавляет одну картинку PNG
- **THEN** выводится `Changes: 2 files, +10 -2`

### Requirement: Только во вкладке своего PR
Строка `Changes:` SHALL показываться только в PR Info, открытом для PR текущей вкладки PR. PR Info, открытое для PR, у которого нет своей вкладки, SHALL NOT содержать эту строку.

#### Scenario: PR Info из списка для другого PR
- **WHEN** пользователь во вкладке PR #10 открывает из списка PR Info для PR #20
- **THEN** в PR Info для #20 строки `Changes:` нет

#### Scenario: PR Info без вкладки PR
- **WHEN** пользователь открывает PR Info из списка, не открывая вкладку PR
- **THEN** строки `Changes:` нет

### Requirement: Появление строки после вычисления
Пока статистика не вычислена, строки `Changes:` SHALL NOT быть в PR Info. Когда статистика вычислена, открытое окно PR Info этой вкладки SHALL перерисоваться со строкой без действий пользователя. Если вычислить статистику не удалось, строки SHALL NOT быть, а ошибка SHALL записываться в журнал плагина без уведомления пользователя.

#### Scenario: PR Info открыт раньше, чем готова статистика
- **WHEN** PR Info открылся при открытии PR, а статистика ещё вычисляется
- **THEN** сначала строки `Changes:` нет, а после вычисления она появляется в том же окне, позиция курсора сохраняется

#### Scenario: Ошибка git
- **WHEN** вычисление статистики завершилось ошибкой git
- **THEN** PR Info показывается без строки `Changes:`, пользователь уведомления не получает

### Requirement: Bitbucket не запрашивается
Вычисление статистики SHALL NOT отправлять запросы к Bitbucket и SHALL использовать только локальный репозиторий вкладки PR.

#### Scenario: Открытие PR Info
- **WHEN** пользователь открывает PR Info во вкладке PR
- **THEN** для строки `Changes:` не выполняется ни одного запроса к Bitbucket
