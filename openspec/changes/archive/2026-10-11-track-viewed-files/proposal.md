# Proposal

## Why

После изменения `track-pr-changes-since-last-view` плагин знает, что изменилось с прошлого открытия PR. Но открытие PR само по себе считается просмотром, поэтому по нему не видно, какие файлы вы действительно посмотрели. Для большого PR, который смотрят за несколько подходов, нужен список файлов, ещё не просмотренных в их текущем виде. Bitbucket Server 8.9.7 отметки «файл просмотрен» не имеет: в Atlassian она есть только в Bitbucket Cloud.

## What Changes

- У каждого файла PR появляется локальное состояние «просмотрен». Файл отмечается автоматически, когда его diff показан во вкладке PR и поверх не открыт PR Info. Переход к файлу из панели Diffview тоже засчитывается.
- Отметка привязана к содержимому файла в ветке PR. Если после просмотра содержимое файла изменилось, он снова считается непросмотренным. Rebase и merge target-ветки, не затронувшие файл, отметку не сбрасывают.
- Панель файлов Diffview показывает состояние просмотра: просмотренные файлы затемнены. **BREAKING** (для неархивированного `track-pr-changes-since-last-view`): знак `◆` у файлов, изменённых с прошлого открытия, из панели убирается.
- В PR Info добавляется строка «Files viewed: x/y».
- PR Info открывается автоматически при каждом открытии вкладки PR, после загрузки комментариев. Пока PR Info открыт, первый файл не отмечается; закрытие окна отмечает его. **BREAKING** (для неархивированного изменения): уведомление «since last view» после открытия и параметр `since_last_view.notify` удаляются, потому что та же сводка всегда видна в PR Info.
- Новая настраиваемая клавиша `<leader>rv`:
  - в обычном режиме переключает отметку файла под курсором в панели или текущего файла в diff-буфере;
  - в визуальном режиме в панели отмечает выделенные файлы как просмотренные, если среди них есть непросмотренный, а если все уже просмотрены, снимает отметку со всех. Строка каталога означает все файлы внутри него.
- Отметки хранятся в записи просмотра PR (`bb_pr_seen.json`), переживают перезапуск Neovim и вытесняются вместе с записью. Свои PR и PR не в состоянии OPEN не отслеживаются, как и в `track-pr-changes-since-last-view`.

## Capabilities

### New Capabilities

- `pr-viewed-files`: состояние просмотра отдельных файлов PR — когда файл считается просмотренным и когда снова становится непросмотренным, ручное переключение, отображение в панели Diffview и PR Info, автооткрытие PR Info при открытии PR.

### Modified Capabilities

(нет в `openspec/specs/`: основных спецификаций в проекте пока нет)

Изменение затрагивает требования капабилити `pr-change-tracking` из неархивированного изменения `track-pr-changes-since-last-view`:

- требование «Уведомление после открытия» удаляется;
- из требования «Пометки файлов в панели Diffview» удаляется пометка файлов по изменениям кода и комментариев с прошлого открытия.

Эти правки вносятся прямо в `openspec/changes/track-pr-changes-since-last-view/specs/pr-change-tracking/spec.md`. Изменение `track-pr-changes-since-last-view` архивируется после реализации этого изменения.

## Impact

- `lua/bb_pr/init.lua`:
  - автокоманда `BufEnter`/`CursorMoved` (отметка показанного файла);
  - `apply_comment_indicators_to_diffview_panel` (затемнение вместо `◆`);
  - `build_pr_info_content` (строка «Files viewed»);
  - `open_diffview` (автооткрытие PR Info);
  - `notify_since_last_view` (удаление);
  - `default_config` и `setup` (клавиша, удаление `notify`).

  В `init.lua` около 198 локальных переменных верхнего уровня при пределе Lua в 200, поэтому новые функции размещаются в модуле или в существующей таблице.
- `lua/bb_pr/seen.lua`: поле `files` в записи.
- `README.md`: описание отметок и клавиши, удаление `notify`.
- Запросов к Bitbucket не добавляется. Добавляются локальные git-вызовы для получения blob-хешей файлов.
