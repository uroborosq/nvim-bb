# Design

## Context

Мотивация описана в proposal.md, требования — в `specs/pr-viewed-files/spec.md`. Изменение опирается на неархивированное `track-pr-changes-since-last-view` и использует его код.

Текущее состояние кода, на которое опирается решение:

- Запись просмотра PR хранится в `bb_pr_seen.json` через модуль `lua/bb_pr/seen.lua`. Модуль не хранит состояния, `put` выполняет read-modify-write одного ключа, запись атомарна, старые записи вытесняются. Запись: `{ seen_at, source, root, comment_count, comments }`.
- `track_tab_view` при открытии вкладки решает, отслеживается ли PR (OPEN, не свой, `since_last_view.enabled`), и создаёт `tab_state().since`. Вкладки без `since` не отслеживаются.
- `tab_state().diff_base = { root, base, source }`, где `source` — sha вершины ветки PR, `base` — merge base с target-веткой. `with_pr_changed_files(diff_base, cb)` даёт файлы PR в виде `{ path, from_path }`, или nil при ошибке git.
- Текущий файл Diffview определяется по `view.cur_entry` (`diffview_window_file`). Строки панели сопоставляются с путями через `collect_diffview_file_rows` (`comp.context.path` → `comp.lstart`). Каталоги — узлы дерева компонентов, внутри которых лежат компоненты файлов.
- Общая автокоманда `BufEnter`/`BufWinEnter`/`CursorMoved`/`WinScrolled` (группа `bb_pr_comments`) срабатывает при любом переходе во вкладке. Тяжёлая работа в ней защищена memo.
- Панель рисуется в `apply_comment_indicators_to_diffview_panel` в пространстве имён `diffview_panel_ns`: знак 💬 для файлов с комментариями и `◆` (virtual text) для изменений с прошлого открытия. Memo — `state.panel_rendered_by_buf`.
- PR Info — плавающее окно, его буфер распознаётся через `pr_info_buffer_pr(buf)`. Сводка «Since Last View» строится в `since_section_lines`. Открывается через `open_pr_info_with_comments(pr)`.
- `notify_since_last_view` выводит уведомление после открытия, флаг `since.notified`, параметр `since_last_view.notify`.
- В `init.lua` около 198 локальных переменных верхнего уровня при пределе Lua в 200 на чанк.

## Goals / Non-Goals

**Goals:**

- Отметка «просмотрен» точно отражает, видел ли пользователь текущее содержимое файла в ветке PR.
- Автоматическая отметка не требует действий пользователя и не ставится за файлы, которые он не видел.
- Обработка перехода между файлами остаётся дешёвой: без git-вызовов и без перерисовки, если файл не сменился.

**Non-Goals:**

- Синхронизация отметок с Bitbucket: в Server/Data Center такой функции нет.
- Отметки на уровне hunk или строк.
- Число непросмотренных файлов в списке PR: для этого нужны blob-хеши каждого PR без открытия вкладки.
- Сброс отметки из-за новых комментариев к файлу (см. D7).
- Действия «отметить всё» и «сбросить всё» отдельными командами: их заменяет визуальное выделение в панели.

## Decisions

### D1. Отметка привязана к blob-хешу файла

Для каждого файла PR хранится blob-хеш его содержимого на момент просмотра. Файл просмотрен, если сохранённый хеш совпадает с текущим.

- Текущие хеши получаются одним асинхронным вызовом `git ls-tree -r -z <source> -- <пути PR>` при открытии вкладки.
- Для удалённых в PR файлов (их нет в `source`) используется второй вызов `git ls-tree -r -z <base> -- <удалённые пути>`, то есть сравнивается удаляемое содержимое.
- Результат хранится в `tab_state().viewed = { blobs = { [path] = sha }, files = { [path] = sha } }`. `files` — копия сохранённых отметок.
- Переименованный файл учитывается по новому пути (`path`), отметка со старого пути не переносится.

Альтернатива — привязать отметку к коммиту `source`. Её отвергли: любой новый коммит сбрасывал бы все файлы, а rebase сбрасывал бы и неизменённые.

Пока хеши не получены (асинхронный вызов не завершился или git завершился ошибкой), файлы не отмечаются и в панели показываются без затемнения. Ошибка пишется в журнал.

### D2. Хранение в записи просмотра

В запись `bb_pr_seen.json` добавляется поле `files = { ["<path>"] = "<blob sha>" }`.

- Пишется через `seen.set_files` в режиме read-modify-write. Перед записью файл перечитывается, и в `files` меняются только затронутые пути. Так отметки из двух экземпляров Neovim по разным файлам не теряются.
- `track_tab_view`, создавая новую запись при открытии, переносит `files` из предыдущей записи.
- Записи без `files` (созданные до этого изменения) читаются как «ничего не просмотрено».
- Отметка снимается удалением ключа пути.

### D3. Когда файл отмечается автоматически

Обработчик выполняется в существующей автокоманде группы `bb_pr_comments`, только для вкладок с `since` и `viewed.blobs`. Он:

1. Берёт путь текущего файла из `view.cur_entry`.
2. Выходит, если путь совпадает с `viewed.last_path`, — дешёвый путь для `CursorMoved`.
3. Выходит, не меняя `last_path`, если во вкладке открыто окно PR Info: перебор окон вкладки и проверка `pr_info_buffer_pr`.
4. Иначе запоминает `last_path`, и если файл ещё не просмотрен в текущем виде, отмечает его (D2) и перерисовывает панель.

Пример: при открытии PR поверх первого файла открыт PR Info, поэтому отметки нет. После закрытия PR Info фокус возвращается в окно Diffview, срабатывает `BufEnter`, и первый файл отмечается.

Выбор файла в панели меняет `cur_entry`, и следующий `BufEnter`/`CursorMoved` во вкладке его отмечает, даже если фокус остался в панели.

Альтернатива — отмечать, только когда курсор попал в diff-окно файла. Её отвергли по решению пользователя: просмотр из панели тоже считается.

### D4. Ручное переключение `<leader>rv`

Настройка `since_last_view.viewed_map` (по умолчанию `<leader>rv`) регистрируется как глобальная клавиша для режимов `n` и `x`, так же, как `diff_map`. Обработчик определяет контекст по текущему буферу:

- **Буфер панели Diffview, режим `n`:** файл под курсором. Строка курсора сопоставляется с путём через обратную таблицу строк панели (`lstart` → путь). На строке каталога действие применяется ко всем файлам каталога.
- **Буфер панели, режим `x`:** все файлы в диапазоне строк выделения, каталоги раскрываются в свои файлы. Если среди них есть непросмотренный, все отмечаются, иначе со всех снимается отметка.
- **Diff-буфер вкладки PR:** текущий файл (`cur_entry`).
- **Вне вкладки отслеживаемого PR:** предупреждение. В своём PR — то же уведомление, что у `<leader>rn`.

Ручное снятие отметки с текущего файла не должно сразу же отмениться автоотметкой из D3. Для этого, если ручное переключение затронуло показанный файл, `viewed.last_path` устанавливается в его путь, и автоотметка сработает только при следующем переходе на этот файл. Переключение других файлов `last_path` не меняет, чтобы не отменить отложенную автоотметку показанного файла (например, пока открыт PR Info).

### D5. Отображение в панели

`apply_comment_indicators_to_diffview_panel` для вкладок с `viewed`:

- на строки просмотренных файлов ставит extmark с `line_hl_group = "BbPrViewedFile"`; группа по умолчанию связана с `Comment`, задаётся с `default = true`;
- знак 💬 не трогает;
- ключ memo панели дополняется счётчиком `viewed.version`, который увеличивается при каждом изменении отметок.

Знак `◆` (`mark_panel_row_since` и множество изменённых файлов) удаляется: в панели остаётся одно понятие «непросмотрен». `since.delta` по-прежнему используется в сводке PR Info и в `<leader>rn`.

### D6. PR Info

- В разделе «Since Last View» добавляется строка `Files viewed: x/y`. Здесь `y` — число файлов PR, `x` — число просмотренных в текущем виде. Пока `viewed.blobs` не получены, строка не выводится.
- PR Info открывается автоматически при каждом открытии вкладки PR: из `open_diffview`, один раз на вкладку, после `show_comments` или после ошибки загрузки комментариев. Используется существующий `open_pr_info_with_comments(pr)` в контексте вкладки PR. Настройки нет. Если вкладка PR в этот момент не активна, PR Info открывается при первом `TabEnter` в неё. При открытии PR с переходом к комментарию файла вместо PR Info открывается окно комментария; если комментарий не найден, открывается PR Info. Переход к overview-комментарию открывает PR Info сам.
- `notify_since_last_view`, флаг `since.notified` и параметр `since_last_view.notify` удаляются. `since_summary` и `since_settled` остаются, если их использует PR Info, иначе тоже удаляются.

### D7. Новые комментарии не сбрасывают отметку

Отметка относится к коду. Новый комментарий к просмотренному файлу виден по пометке `[new]` в virtual text и в PR Info, но файл не становится непросмотренным. Это допущение: в обсуждении явно не решалось.

### D8. Размещение кода

Чистая логика выносится в новый модуль `lua/bb_pr/viewed.lua`:

- разбор вывода `ls-tree`;
- проверка «просмотрен»;
- подсчёт `x/y`;
- выбор действия для выделения.

Модуль тестируется headless без Diffview. Интеграция с вкладкой, автокомандой, панелью и PR Info размещается в `init.lua` внутри одной таблицы (например, существующей `seen_view` или новой `viewed_view`). Новых локальных переменных верхнего уровня — не больше одной, плюс `require` модуля, если `viewed_view` не используется. Удаление `notify_since_last_view` и `mark_panel_row_since` освобождает две.

## Risks / Trade-offs

- [Файл показан мельком при перелистывании `]f`] → Он отмечается, хотя пользователь его не читал. Это следствие выбранного правила. Отметку снимает `<leader>rv`.
- [`git ls-tree` для большого PR] → Один вызов на открытие вкладки, асинхронно. Затраты сопоставимы с уже существующим `git diff --name-status`.
- [Два экземпляра Neovim отмечают файлы одного PR] → read-modify-write по путям сохраняет отметки обоих. Снятие отметки в одном и отметка в другом для одного пути — побеждает последняя запись.
- [Запись без `files` от предыдущей версии] → Все файлы непросмотрены при первом открытии после обновления. Это допустимо.
- [Удаление уведомления] → Пользователи с `since_last_view.notify` в `setup` получат неизвестный ключ. `merge_config` неизвестные ключи не проверяет, поэтому ошибки не будет.

## Migration Plan

Миграции данных нет: поле `files` добавляется при первой отметке. Изменение `track-pr-changes-since-last-view` архивируется после реализации этого изменения, иначе основная спецификация `pr-change-tracking` на время будет содержать удалённые требования.

Откат: `since_last_view.enabled = false` выключает и отметки просмотра.

## Open Questions

- Какой из User-событий Diffview (`DiffviewDiffBufWinEnter`) или существующей автокоманды надёжнее отражает смену `cur_entry` при выборе файла в панели без смены фокуса. Уточняется при реализации D3 тестом с настоящим diffview.nvim; на поведение это не влияет.
