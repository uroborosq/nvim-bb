# Design

## Context

Мотивация описана в proposal.md, требования — в `specs/pr-diff-stats/spec.md`.

Текущее состояние кода, на которое опирается решение:

- `open_diffview` после `DiffviewOpen` вызывает `set_current_tab_diff_base`, и тот задаёт `tab_state().diff_base = { root, base, source }`: `base` — merge base `origin/<from>` и `origin/<to>`, `source` — вершина `origin/<from>`. При каждом открытии создаётся новый объект `diff_base`.
- `with_pr_changed_files(info, cb)` выполняет `git diff --name-status -z -M base source`, кэширует `{ from_path, path }[]` в `info.changed_files` и вызывает `cb` в главном цикле, а при ошибке git вызывает `cb(nil)`. Параллельные вызовы до первого результата запускают отдельные процессы git.
- `with_pr_changed_files` вызывается только из трёх мест: prefetch файлов с комментариями (если комментарии к файлам есть), отслеживание viewed (только чужие OPEN PR) и `:BBPRSinceLastView`. Для своего PR без комментариев к файлам список файлов не строится.
- PR Info строится в `build_pr_info_content(pr, tabpage, comments)` из `tab_state(tabpage)`. Шапка — строки `PR #`, `Title:`, `Opened:`, а строка `Merge: CONFLICT` вставляется на позицию 4. Раздел «Since Last View» показывается только при `tab_since(tabpage, pr)`, то есть когда PR Info относится к PR вкладки.
- `seen_view.refresh_info(tabpage)` перерисовывает открытые окна PR Info для PR вкладки и сохраняет позицию курсора.
- В `init.lua` около 198 локальных переменных верхнего уровня при пределе Lua в 200. Новые функции размещаются в модуле или в существующей таблице (как `seen_view.viewed_lib`).

## Goals / Non-Goals

**Goals:**

- Статистика и список файлов PR получаются одним вызовом git на `diff_base`.
- Строка появляется в уже открытом PR Info без действий пользователя.

**Non-Goals:**

- Статистика для PR без вкладки (PR Info из списка): нет merge base, а `origin/<branch>` может быть устаревшим.
- Статистика в списке PR.
- Статистика изменений с последнего просмотра (`baseline..source`).
- Числа по отдельным файлам в панели Diffview. Панель Diffview показывает свои `+/-` относительно рабочего дерева с влитой target-веткой, и они могут не совпадать со строкой `Changes:`.

## Decisions

### D1. `--numstat` вместо `--name-status`

`with_pr_changed_files` выполняет `git diff --numstat -z -M <base> <source>`. Формат вывода `-z`:

```
<added>\t<deleted>\t<path>\0                  обычный файл
<added>\t<deleted>\t\0<from_path>\0<path>\0   переименование (путь пуст, далее два пути)
-\t-\t<path>\0                                бинарный файл
```

(Формат проверен на git: переименование `x.txt` → `y y.txt` с одной добавленной строкой дало `1\t0\t\0x.txt\0y y.txt\0`, бинарный файл дал `-\t-\tbin\0`.)

Элементы `changed_files` сохраняют поля `from_path` и `path` с тем же смыслом и получают поля `added`/`deleted`: числа или nil для бинарного файла. Сводка сохраняется рядом: `info.line_stats = { files, added, deleted }`.

Флаг `-M` с порогом по умолчанию сохраняется, поэтому список файлов для текущих потребителей не меняется: удалённый файл, как и раньше, даёт `from_path == path`. `--name-status` дополнительно сообщает букву статуса, но её никто не использует.

Альтернатива — отдельный вызов `git diff --shortstat`. Её отвергли: это второй процесс git на тот же диапазон, а сумма по `numstat` получается без дополнительных затрат.

Без `-w` и без `--ignore-*`: Bitbucket по умолчанию учитывает изменения в пробелах.

### D2. Разбор вывода — чистая функция в модуле

Разбор `numstat -z` выносится в чистую функцию модуля `lua/bb_pr/diffstat.lua`: `parse_numstat(out)` → `files, totals`. Её можно проверить headless-скриптом без репозитория. Модуль подключается без новой top-level `local`, например как поле `seen_view` (по примеру `seen_view.viewed_lib`) или через `require` внутри `with_pr_changed_files`.

### D3. Один процесс git на `diff_base`

У `with_pr_changed_files` появляется очередь ожидающих: пока процесс git выполняется, повторные вызовы добавляют `cb` в `info.changed_files_waiters` и не запускают новый процесс. По завершении вызываются все ожидающие. Это нужно, потому что D4 запускает вычисление при каждом открытии, и оно будет пересекаться с вызовом из отслеживания viewed.

### D4. Запуск при открытии вкладки

Сразу после `set_current_tab_diff_base` в `open_diffview`, если `diff_base` задан, вызывается `with_pr_changed_files(diff_base, ...)`. В обработчике результата проверяется, что вкладка жива и `tab_state(tabpage).diff_base` — тот же объект (вкладку не открыли заново), затем вызывается `seen_view.refresh_info(tabpage)`. Если PR Info ещё не открыт, ничего не перерисовывается: при открытии он прочитает `line_stats` из `diff_base`.

Альтернатива — запуск при открытии PR Info. Её отвергли: PR Info открывается автоматически после загрузки комментариев, и тогда вычисление начиналось бы позже. При запуске сразу после `DiffviewOpen` git работает параллельно с загрузкой комментариев.

### D5. Строка в `build_pr_info_content`

Строка выводится, если `ts.diff_base.line_stats` задан и PR Info относится к PR вкладки (`ts.pr.id == pr.id`, по тому же правилу, что и в `tab_since`, но без требования `since`, потому что свои PR тоже получают строку). Строка вставляется сразу после `Opened:`, до строки `Merge: CONFLICT`. Формат: `Changes: <files> files, +<added> -<deleted>`. Слово `files` не склоняется по числу, как и в остальных строках шапки (например, `Files viewed: 1/12`).

### D6. Ошибка

При ошибке git `with_pr_changed_files` уже пишет в журнал и вызывает `cb(nil)`. `line_stats` остаётся nil, строки нет, уведомления нет. Повторной попытки в той же вкладке не делается: следующее открытие PR создаёт новый `diff_base`.

## Risks / Trade-offs

- [Числа в PR Info расходятся с `+/-` в панели Diffview] → Панель считает относительно рабочего дерева с влитой target-веткой. Расхождение описывается в README.
- [Если ветку PR после открытия обновили на сервере, числа отражают состояние на момент последнего `git fetch` при открытии вкладки] → Это то же поведение, что и у самого diff во вкладке. Переоткрытие PR обновляет числа.
- [Большой PR: `numstat` дороже, чем `name-status`, потому что git считает построчный diff каждого файла] → Вызов асинхронный и не задерживает открытие. Время для PR с сотнями файлов проверяется в задаче ручной проверки. При заметной задержке «Files viewed» и prefetch по-прежнему ждут тот же результат, поэтому стоит сравнить задержку с прежним `--name-status`.
- [Порядок с `Merge: CONFLICT`] → Конфликт теперь вторая строка после `Opened:`, а не первая. Это осознанный выбор, зафиксированный в спецификации.
