# Proposal

## Why

При повторном открытии PR приходится заново просматривать весь diff и все комментарии, чтобы понять, что изменилось с прошлого раза: какие коммиты добавил автор и какие комментарии и ответы появились. Bitbucket Server 8.9.7 эту задачу не решает. Поле участника `lastReviewedCommit` заполняется только при выставлении статуса Approve или Needs Work. На сервере `bitbucket.example.com` 2026-10-11 проверено: среди открытых PR оно заполнено у 1 из 158 ревьюеров со статусом UNAPPROVED и у 7 из 7 со статусами APPROVED или NEEDS_WORK. Просмотр PR в веб-интерфейсе это поле не обновляет. Для «новых комментариев» у Bitbucket механизма нет вообще.

## What Changes

- Плагин запоминает момент каждого открытия вкладки открытого (OPEN) PR, автор которого — не текущий пользователь: коммит вершины ветки PR, версии всех увиденных комментариев и их общее число. Данные хранятся локально в JSON в `stdpath("state")`. Увиденный коммит дополнительно закрепляется git-ссылкой в репозитории, чтобы он оставался доступным после force push и `git gc`. Для влитых и отклонённых PR ничего не хранится и не показывается; запись удаляется, когда PR встречается в таком состоянии.
- При открытии PR его состояние сравнивается с предыдущей записью. Новое отображается до закрытия вкладки:
  - одно уведомление после открытия, если с прошлого просмотра есть новые коммиты или комментарии;
  - сводка «с последнего просмотра» в окне PR Info: время прошлого просмотра, число новых коммитов, новых и изменённых комментариев;
  - пометки «новый» и «изменён» у overview- и file-комментариев в PR Info, а также в виртуальном тексте diff-буферов;
  - пометка в панели файлов Diffview у файлов, которые изменились в коде или получили новые комментарии с последнего просмотра.
- Новая настраиваемая клавиша `<leader>rn` открывает отдельный Diffview «увиденный коммит..текущая вершина ветки PR». Если автор за это время влил target-ветку или сделал rebase, diff ограничивается файлами PR.
- Точкой отсчёта для кода служит более поздний из двух коммитов: локальной записи и `lastReviewedCommit` текущего пользователя в Bitbucket. Для комментариев используется только локальная запись.
- В списке PR (Telescope и простой буфер) появляется маркер: PR ещё не открывался, есть новые коммиты, выросло число комментариев и задач. Маркер вычисляется без дополнительных запросов.
- Свои PR (пользователь — автор) не отслеживаются.
- Go CLI:
  - исправляется чтение `commentCount`: Bitbucket 8.9.7 отдаёт его только в `properties`, поэтому сейчас поле всегда равно 0; вместе с ним читаются `openTaskCount` и `resolvedTaskCount`;
  - в JSON PR добавляются `my_last_reviewed_commit` и признак авторства `is_mine`;
  - в JSON комментариев добавляется `is_mine`. Собственные комментарии новыми не помечаются.

## Capabilities

### New Capabilities

- `pr-change-tracking`: запись факта просмотра PR и вычисление того, что изменилось с предыдущего просмотра (код и комментарии), а также отображение этих изменений в PR-вкладке, PR Info и списке PR.

### Modified Capabilities

(нет; основных спецификаций в проекте пока нет)

## Impact

- `lua/bb_pr/init.lua`:
  - `open_diffview`: запись просмотра и уведомление;
  - `set_tab_comments` и `reload_tab_comments`: пополнение записи увиденными комментариями;
  - `build_pr_info_content`, `append_comment_lines`, `render_buffer_comments`: пометки;
  - `apply_comment_indicators_to_diffview_panel`: панель файлов;
  - `format_pr_entry` и `build_lines`: маркер в списке;
  - `default_config` и `setup`: новая секция конфигурации и клавиша.
- `main.go`:
  - `PullRequest.UnmarshalJSON`: `commentCount`, `openTaskCount`, `resolvedTaskCount` из `properties` (исправляет и колонку CMTS табличного вывода);
  - поле `LastReviewedCommit` в `Reviewer`, `my_last_reviewed_commit` и `is_mine` в выводе PR;
  - `is_mine` в `PRCommentView`.

  Обратная совместимость сохраняется: поля только добавляются.
- Новый файл состояния `stdpath("state")/bb_pr_seen.json` и git-ссылки `refs/bb_pr/seen/<project>/<repo>/<id>` в репозитории ревью.
- `README.md`: описание фичи, маркеров и новой клавиши.
- Запросов к Bitbucket не добавляется, на сервер ничего не записывается.
