# Spec Delta

## Purpose

Позволяет ревьюеру при повторном открытии PR сразу увидеть, что изменилось с его предыдущего просмотра: новые коммиты и новые или изменённые комментарии. Повторно просматривать весь PR для этого не требуется.

## ADDED Requirements

### Requirement: Отслеживаются только открытые чужие PR
Плагин SHALL отслеживать просмотры только PR в состоянии OPEN, автор которых — не текущий пользователь. Для своих PR и для PR в состоянии MERGED или DECLINED плагин SHALL NOT создавать записи просмотра, показывать пометки, сводку и маркер в списке. Когда PR встречается в состоянии MERGED или DECLINED (в списке PR или при открытии вкладки), его запись просмотра и закрепляющая ссылка SHALL удаляться.

#### Scenario: Свой PR
- **WHEN** пользователь открывает вкладку PR, автором которого является он сам
- **THEN** запись просмотра не создаётся, пометок нет, а в списке PR колонка маркера у этого PR пустая

#### Scenario: Diff с последнего просмотра в своём PR
- **WHEN** пользователь нажимает `<leader>rn` во вкладке своего PR
- **THEN** Diffview не открывается, выводится уведомление «для своих PR отслеживание отключено»

#### Scenario: PR влит после просмотра
- **WHEN** пользователь просматривал PR #101, PR был влит, и затем пользователь открывает список PR с состоянием MERGED
- **THEN** у PR #101 нет маркера, а его запись просмотра и ссылка удалены

### Requirement: Открытие вкладки PR записывает просмотр
Плагин SHALL при каждом успешном открытии вкладки отслеживаемого PR сохранять запись просмотра: время просмотра, коммит вершины ветки PR, число и версии всех полученных комментариев, включая задачи. Запись SHALL сохраняться локально и переживать перезапуск Neovim. Открытие окна PR Info из списка PR без открытия вкладки просмотром не считается.

#### Scenario: Первое открытие PR
- **WHEN** пользователь открывает вкладку PR #101, для которого нет записи просмотра
- **THEN** создаётся запись с текущим коммитом вершины ветки PR, числом и версиями полученных комментариев

#### Scenario: Просмотр PR Info без вкладки
- **WHEN** пользователь открывает PR Info из списка PR, не открывая вкладку PR
- **THEN** запись просмотра этого PR не создаётся и не изменяется, сводки и пометок в окне нет

#### Scenario: Ошибка открытия
- **WHEN** открытие вкладки PR прерывается (неудачный `git fetch` или checkout, грязное рабочее дерево)
- **THEN** запись просмотра не изменяется

### Requirement: Точка сравнения фиксируется на время вкладки
При открытии вкладки PR плагин SHALL запомнить для этой вкладки предыдущую запись просмотра и сравнивать с ней всё, что показывается во вкладке, до её закрытия. Обновление записи при открытии и при перезагрузке комментариев SHALL NOT менять точку сравнения уже открытой вкладки.

#### Scenario: Пометки сохраняются после записи просмотра
- **WHEN** пользователь открывает PR, в котором с прошлого просмотра появились два комментария, и затем перезагружает комментарии клавишей обновления
- **THEN** оба комментария по-прежнему помечены как новые

#### Scenario: Повторное открытие
- **WHEN** пользователь закрывает вкладку PR и открывает тот же PR снова, а изменений на сервере за это время не было
- **THEN** ни один коммит и ни один комментарий не помечен как новый

### Requirement: Комментарии, увиденные во вкладке, добавляются в запись
Плагин SHALL добавлять в запись просмотра версии комментариев и обновлять их общее число при каждой загрузке комментариев в открытой вкладке PR, включая собственные комментарии пользователя.

#### Scenario: Комментарий пришёл при обновлении
- **WHEN** во время открытой вкладки PR другой участник оставляет комментарий, пользователь обновляет комментарии и затем открывает PR повторно
- **THEN** при повторном открытии этот комментарий не помечен как новый

#### Scenario: Свой комментарий из вкладки
- **WHEN** пользователь оставляет комментарий во вкладке PR, закрывает вкладку и открывает список PR
- **THEN** у этого PR нет маркера роста числа комментариев

### Requirement: Классификация комментариев
Относительно точки сравнения вкладки плагин SHALL считать комментарий новым, если его id нет в записи, и изменённым, если его версия отличается от записанной, в том числе после resolve или смены состояния задачи. Собственные комментарии пользователя SHALL NOT помечаться ни новыми, ни изменёнными. Правило одинаково для overview- и file-комментариев, включая ответы.

#### Scenario: Новый ответ в ветке обсуждения
- **WHEN** с прошлого просмотра коллега ответил в существующей ветке file-комментария
- **THEN** ответ помечен как новый, остальные комментарии ветки не помечены

#### Scenario: Отредактированный комментарий
- **WHEN** с прошлого просмотра автор изменил текст overview-комментария, увиденного ранее
- **THEN** комментарий помечен как изменённый

#### Scenario: Задача выполнена
- **WHEN** с прошлого просмотра автор PR отметил выполненной задачу, увиденную ранее
- **THEN** задача помечена как изменённая

#### Scenario: Собственный комментарий
- **WHEN** пользователь оставил комментарий в веб-интерфейсе Bitbucket после прошлого просмотра в плагине
- **THEN** этот комментарий не помечен как новый

### Requirement: Без предыдущей записи комментарии не помечаются
Если для PR нет записи просмотра, плагин SHALL NOT помечать комментарии как новые и изменённые. Для кода SHALL использоваться точка отсчёта из Bitbucket (см. соответствующее требование), а при её отсутствии изменения кода с последнего просмотра SHALL считаться неизвестными.

#### Scenario: Первое открытие PR с комментариями
- **WHEN** пользователь впервые открывает PR с десятью комментариями и без `lastReviewedCommit` в Bitbucket
- **THEN** ни один комментарий не помечен, сводка в PR Info сообщает, что PR открывается впервые

### Requirement: Точка отсчёта кода — более поздняя из локальной и Bitbucket
Точкой отсчёта для изменений кода плагин SHALL считать более поздний из двух коммитов: коммит локальной записи просмотра и `lastReviewedCommit` текущего пользователя среди ревьюеров PR в Bitbucket. Коммит из Bitbucket считается более поздним, если коммит записи — его предок и они не совпадают. Если доступен только один из коммитов, используется он. Для комментариев точка отсчёта из Bitbucket SHALL NOT применяться.

#### Scenario: PR одобрен в веб-интерфейсе, записи нет
- **WHEN** пользователь одобрил PR в веб-интерфейсе на коммите A, затем автор добавил коммит B, и пользователь впервые открывает PR в плагине
- **THEN** изменения кода считаются от коммита A, а `<leader>rn` показывает diff A..B

#### Scenario: Ревью в веб-интерфейсе позже просмотра в плагине
- **WHEN** пользователь просмотрел PR в плагине на коммите A, затем автор добавил B, пользователь одобрил PR в веб-интерфейсе на B, автор добавил C, и пользователь открывает PR в плагине
- **THEN** изменения кода считаются от коммита B, а комментарии сравниваются с записью просмотра на A

### Requirement: Сводка изменений в PR Info
Окно PR Info для PR открытой вкладки SHALL содержать раздел со сводкой изменений с последнего просмотра. В разделе указаны время предыдущего просмотра или отметка о первом открытии, число новых коммитов либо факт переписывания истории ветки, число новых и число изменённых комментариев.

#### Scenario: Есть новые коммиты и комментарии
- **WHEN** с прошлого просмотра автор добавил 3 коммита и появилось 2 новых комментария
- **THEN** сводка показывает время прошлого просмотра, «3 новых коммита» и «2 новых комментария»

#### Scenario: Force push
- **WHEN** с прошлого просмотра ветка PR была переписана и увиденный коммит больше не является её предком
- **THEN** сводка сообщает, что история ветки переписана, вместо числа новых коммитов

### Requirement: Пометки новых и изменённых комментариев
Плагин SHALL визуально помечать новые и изменённые комментарии в PR Info (overview- и file-комментарии), во всплывающем окне комментариев строки и в виртуальном тексте diff-буферов. Пометки «новый» и «изменён» SHALL различаться.

#### Scenario: Новый file-комментарий в diff-буфере
- **WHEN** пользователь открывает файл, к строке которого с прошлого просмотра добавлен комментарий
- **THEN** виртуальный текст этой строки содержит пометку «новый»

#### Scenario: Новый overview-комментарий в PR Info
- **WHEN** с прошлого просмотра добавлен overview-комментарий
- **THEN** в PR Info заголовок этого комментария содержит пометку «новый»

### Requirement: Diff изменений с последнего просмотра
Клавиша `<leader>rn` во вкладке PR SHALL открывать отдельный Diffview между коммитом точки отсчёта и текущей вершиной ветки PR. Если они совпадают или точки отсчёта нет, Diffview SHALL NOT открываться, а пользователь получает уведомление о причине.

#### Scenario: Новые коммиты есть
- **WHEN** пользователь нажимает `<leader>rn`, а с прошлого просмотра в ветку PR добавлены коммиты
- **THEN** открывается Diffview «увиденный коммит..текущая вершина ветки PR»

#### Scenario: Новых коммитов нет
- **WHEN** пользователь нажимает `<leader>rn`, а вершина ветки PR не изменилась
- **THEN** Diffview не открывается, выводится уведомление «нет новых коммитов с последнего просмотра»

### Requirement: Diff ограничен файлами PR при смене merge base
Если merge base ветки PR с target-веткой изменился с момента точки отсчёта (автор влил target-ветку или сделал rebase), diff изменений с последнего просмотра SHALL включать только файлы, которые изменяет сам PR. Пользователь SHALL получить уведомление об этом ограничении. Смена merge base SHALL определяться одинаково для точки отсчёта из локальной записи и из Bitbucket.

#### Scenario: Автор влил target-ветку
- **WHEN** после прошлого просмотра автор влил `master` в ветку PR и изменил один свой файл
- **THEN** diff `<leader>rn` содержит только файлы PR, а изменения из `master` в файлах вне PR не показываются

### Requirement: Увиденный коммит доступен после force push
Плагин SHALL сохранять увиденный коммит в локальном репозитории ревью так, чтобы он оставался доступен для diff после force push ветки PR и после `git gc`.

#### Scenario: Force push после просмотра
- **WHEN** пользователь просмотрел PR на коммите A, автор сделал force push с коммитом B, и пользователь нажимает `<leader>rn`
- **THEN** открывается Diffview A..B

#### Scenario: Коммит недоступен
- **WHEN** точка отсчёта взята из Bitbucket, а коммита нет в локальном репозитории и получить его с сервера не удалось
- **THEN** Diffview не открывается, выводится уведомление о недоступности коммита

### Requirement: Маркер в списке PR
Строка отслеживаемого PR в списке PR (Telescope и простой буфер) SHALL показывать маркер: PR не открывался; есть новые коммиты; выросло число комментариев и задач (с приростом). Без записи просмотра новые коммиты SHALL определяться по `lastReviewedCommit` из Bitbucket, а прирост комментариев SHALL NOT показываться. Маркер SHALL вычисляться без запросов к Bitbucket, порядок строк SHALL NOT меняться.

#### Scenario: Новые коммиты в просмотренном PR
- **WHEN** пользователь открывает список PR, а у PR #102 вершина ветки отличается от записанной
- **THEN** строка PR #102 содержит маркер новых коммитов

#### Scenario: Новые комментарии и задачи
- **WHEN** с прошлого просмотра PR #102 в нём появились 2 комментария и 1 задача
- **THEN** строка PR #102 содержит маркер `+3`

#### Scenario: PR не открывался, но одобрен в веб-интерфейсе
- **WHEN** у PR нет записи просмотра, пользователь одобрил его в Bitbucket на коммите A, а вершина ветки теперь B
- **THEN** строка PR содержит маркер новых коммитов, а не маркер «не открывался»

#### Scenario: PR не открывался
- **WHEN** в списке есть PR без записи просмотра и без `lastReviewedCommit` пользователя
- **THEN** его строка содержит маркер «не открывался»

### Requirement: Настройка
Секция конфигурации фичи SHALL позволять отключить отслеживание целиком и переназначить клавишу diff изменений с последнего просмотра. Значение клавиши по умолчанию SHALL начинаться с `<leader>r`. При отключённом отслеживании запись просмотров, пометки и маркеры SHALL отсутствовать.

#### Scenario: Отслеживание отключено
- **WHEN** пользователь передаёт в `setup` отключение отслеживания и открывает PR
- **THEN** запись просмотра не создаётся, пометок и маркера в списке нет

### Requirement: Ограничение объёма хранилища
Хранилище записей просмотра SHALL хранить не больше настраиваемого числа PR. При превышении SHALL удаляться записи с самым старым временем просмотра вместе с закрепляющими их ссылками в репозитории.

#### Scenario: Превышение лимита
- **WHEN** лимит равен 200, записей уже 200, и пользователь открывает новый PR
- **THEN** запись с самым старым временем просмотра удаляется, запись нового PR добавляется

### Requirement: Bitbucket не изменяется
Отслеживание изменений SHALL NOT отправлять в Bitbucket запросы, изменяющие данные, и SHALL NOT менять статус ревью или состав участников PR.

#### Scenario: Открытие PR не-ревьюером
- **WHEN** пользователь, не являющийся ревьюером, открывает PR
- **THEN** список участников PR в Bitbucket не меняется

### Requirement: Счётчики комментариев PR читаются из ответа Bitbucket
Go CLI SHALL выводить в JSON PR число комментариев, число открытых и число выполненных задач, полученные от Bitbucket, а табличный вывод SHALL показывать фактическое число комментариев.

#### Scenario: PR с комментариями
- **WHEN** у PR в Bitbucket 30 комментариев и 16 выполненных задач
- **THEN** `bb -json` выдаёт для него `commentCount: 30`, `openTaskCount: 0`, `resolvedTaskCount: 16`
